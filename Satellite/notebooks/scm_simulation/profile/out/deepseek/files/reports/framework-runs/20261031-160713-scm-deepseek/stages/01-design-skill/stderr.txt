- You need a minimal local starter for causal-inference workflows in Python.

\name{synth}
\alias{synth}
\title{
Constructs synthetic control units for comparative case studies
}
\description{
Implements the synthetic control method for causal inference in comparative case studies as developed in Abadie and Gardeazabal (2003) and Abadie, Diamond, and Hainmueller (2010, 2011, 2014). \code{\link{synth}} estimates the effect of an intervention by comparing the evolution of an aggregate outcome for a unit affected by the intervention to the evolution of the same aggregate outcome for a synthetic control group.

\code{\link{synth}} constructs this synthetic control group by searching for a weighted combination of control units chosen to approximate the unit affected by the intervention in terms of characteristics that are predictive of the outcome. The evolution of the outcome for the resulting synthetic control group is an estimate of the counterfactual of what would have been observed for the affected unit in the absence of the intervention.

\code{\link{synth}} can also be used to conduct a variety of placebo and permutation tests that produce informative inference regardless of the number of available comparison units and the number of available time periods. See Abadie and Gardeazabal (2003), Abadie, Diamond, and Hainmueller (2010, 2011, 2014) for details.

\code{\link{synth}} requires the user to supply four matrices as its main arguments. These matrices are named X0, X1, Z1, and Z0 accordingly. X1 and X0 contain the predictor values for the treated unit and the control units respectively. Z1 and Z0 contain the outcome variable for the pre-intervention period for the treated unit and the control units respectively. The pre-intervention period refers to the time period prior to the intervention, over which the mean squared prediction error (MSPE) should be minimized. The MSPE refers to the squared deviations between the outcome for the treated unit and the synthetic control unit summed over all pre-intervention periods specified in Z1 and Z0.

Creating the matrices X1, X0, Z1, and Z0 from a (panel) dataset can be tedious. Therefore, the \pkg{Synth} package offers a preparatory function called \code{\link{dataprep}} that allows the user to easily create all inputs required for \code{\link{synth}}. By first calling \code{\link{dataprep}}, the user creates a single list object called \code{data.prep.obj} that contains all essential data elements to run \code{synth}.

A usual sequence of commands to implement the synthetic control method is to first call \code{\link{dataprep}} to prepare the data, then call \code{\link{synth}} to construct the synthetic control group, and finally summarize results using the functions \code{\link{synth.tab}}, \code{\link{path.plot}}, or \code{\link{gaps.plot}}.

An example of this sequence is provided in the documentation to \code{\link{dataprep}}. This procedure is strongly recommended. Alternatively, the user may provide their own preprocessed data matrices and load them into \code{\link{synth}} via the X0, X1, Z1, and Z0 arguments. In this case, no \code{data.prep.obj} should be specified.

# estimate_synthetic_control.R

parse_args <- function(argv) {
  opts <- list(
    panel = NULL,
    out = \"answer.json\",
    summary_out = NULL,
    treated_unit = \"treated\",
    treated_periods = NULL,
    pre_start = NA_real_,

    optimxmethod = c(\"Nelder-Mead\", \"BFGS\"),
    genoud = FALSE,
    allow_fallback = FALSE,
    describe = FALSE
  )
  i <- 1L
  n <- length(argv)
  split_list <- function(x) trimws(strsplit(x, \",\")[[1]])
  while (i <= n) {
    key <- argv[[i]]
    need <- function() {
      if (i + 1L > n) fail(\"Missing value for argument \", key)
      argv[[i + 1L]]
    }
    if (key == \"--panel\") { opts"'$panel <- need(); i <- i + 2L }
    else if (key == "--out") { opts$out <- need(); i <- i + 2L }
    else if (key == "--summary-out") { opts$summary_out <- need(); i <- i + 2L }
    else if (key == "--treated-unit") { opts$treated_unit <- need(); i <- i + 2L }
    else if (key == "--treated-periods") { opts$treated_periods <- as.numeric(split_list(need())); i <- i + 2L }
    else if (key == "--pre-period-start") { opts$pre_start <- as.numeric(need()); i <- i + 2L }
    else if (key == "--pre-period-end") { opts$pre_end <- as.numeric(need()); i <- i + 2L }
    else if (key == "--predictors") { opts$predictors <- split_list(need()); i <- i + 2L }
    else if (key == "--lag-periods") { opts$lag_periods <- as.numeric(split_list(need())); i <- i + 2L }
    else if (key == "--custom-v") { opts$custom_v <- as.numeric(split_list(need())); i <- i + 2L }
    else if (key == "--optimxmethod") { opts$optimxmethod <- split_list(need()); i <- i + 2L }
    else if (key == "--genoud") { opts$genoud <- TRUE; i <- i + 1L }
    else if (key == "--allow-fallback") { opts$allow_fallback <- TRUE; i <- i + 1L }
    else if (key == "--describe-panel") { opts$describe <- TRUE; i <- i + 1L }

  }

}

read_panel <- function(path) {
  if (is.null(path)) fail("--panel is required (panel CSV path).")
  if (!file.exists(path)) fail("Panel file not found: ", path)
  df <- tryCatch(
    utils::read.csv(path, stringsAsFactors = FALSE, check.names = FALSE),
    error = function(e) fail("Could not read panel CSV: ", conditionMessage(e))
  )
  required <- c("unit_id", "period", "treatment_group", "Z1", "Z2", "Y_observed")
  missing <- setdiff(required, names(df))
  if (length(missing) > 0L) {
    fail("Panel is missing required columns: ", paste(missing, collapse = ", "),
         ". Found columns: ", paste(names(df), collapse = ", "))
  }
  if (nrow(df) == 0L) fail("Panel has zero rows.")
  df$period <- suppressWarnings(as.numeric(df$period))
  df$Y_observed <- suppressWarnings(as.numeric(df$Y_observed))
  if (any(is.na(df$period))) fail("Panel '"'period' column has non-numeric values.\")
  if (any(is.na(df"'$Y_observed))) fail("Panel '"'Y_observed' column has non-numeric values.\")
  df
}

panel_summary <- function(df, treated_unit) {
  units <- unique(df"'$unit_id)
  if (!(treated_unit %in% units)) {
    fail("Treated unit '"'\", treated_unit, \"' not found. Available unit_id values: \",
         paste(head(units, 20), collapse = \", \"))
  }
  donors <- setdiff(units, treated_unit)
  treated_rows <- df[df"'$unit_id == treated_unit, ]
  list(
    panel_rows = nrow(df),
    unit_count = length(units),
    donor_count = length(donors),
    treated_unit = treated_unit,
    donors = donors,
    period_min = min(df$period),
    period_max = max(df$period),
    period_count = length(unique(df$period)),
    treated_group_periods = sort(unique(treated_rows$period[treated_rows$treatment_group == "treated"])),
    null_Y_rows = sum(is.na(df$Y_observed))
  )
}

coerce_treated_periods <- function(df, opts) {
  treated_rows <- df[df$unit_id == opts$treated_unit, ]
  auto <- sort(unique(treated_rows$period[treated_rows$treatment_group == "treated"]))
  tp <- opts$treated_periods %||% auto
  if (length(tp) == 0L) {
    fail("No treated periods. Pass --treated-periods or set treatment_group == '"'treated' for the treated unit.\")
  }
  tp <- sort(unique(as.numeric(tp)))
  missing <- setdiff(tp, unique(treated_rows"'$period))
  if (length(missing) > 0L) {
    fail("Treated periods not present for the treated unit: ", paste(missing, collapse = ", "))
  }
  tp
}

resolve_common_panel <- function(df, treated_unit) {
  # Keep only periods where every unit has an observation so the matrices align.
  donors <- setdiff(unique(df$unit_id), treated_unit)
  keep_units <- c(treated_unit, donors)
  df <- df[df$unit_id %in% keep_units, ]
  tab <- table(df$unit_id, df$period)
  complete_periods <- as.numeric(colnames(tab)[apply(tab, 2, function(col) all(col >= 1L))])
  if (length(complete_periods) == 0L) fail("No period has observations for every unit.")
  df[df$period %in% complete_periods, ]
}

build_predictor_value <- function(df, col, pre_periods) {
  sub <- df[df$period %in% pre_periods, c("unit_id", col)]
  agg <- tapply(sub[[col]], sub$unit_id, function(x) mean(as.numeric(x), na.rm = TRUE))
  agg
}

fallback_donor_mean <- function(df, treated_unit, donors, treated_periods) {
  cf <- vapply(treated_periods, function(p) {
    vals <- df$Y_observed[df$unit_id %in% donors & df$period == p]
    mean(vals, na.rm = TRUE)
  }, numeric(1))
  names(cf) <- as.character(treated_periods)
  cf
}

write_json <- function(payload, path) {

# Synthetic Control ATT Starter (Abadie-Diamond-Hainmueller)

## Purpose

Estimate the counterfactual outcome of a single treated unit in each treated
period and the average treatment effect on the treated (ATT) from a panel of
that unit plus untreated donor units, using the synthetic control method of
Abadie, Diamond and Hainmueller (2010) via the "'`Synth` R package. The skill
turns a `*_panel.csv` file into the required `answer.json`
(`counterfactual`, `att`, `rationale`).

## When to use

- You have panel data with one treated unit, several untreated donor units, and
  a clear pre-treatment window over which the donors can be weighted to
  reproduce the treated unit.
- The intervention is a discrete event affecting a single unit (a state, region,
  firm, or country), and you want a transparent, donor-weighted counterfactual.
- The task names the treated periods explicitly (or they are inferable from a
  `treatment_group` contrast).

## When not to use

- Many treated units with a common intervention time: use a staggered/multi-unit
  difference-in-differences or synthetic DiD design instead of a single-unit SCM.
- You only need an average effect over a randomized/observational cohort with a
  single cross-section: use `dowhy-average-treatment-effect-starter`.
- You have fewer than two donor units, or no pre-treatment periods to fit — the
  estimator will refuse to run.
- The panel has time-varying covariates that also change because of treatment;
  those must be excluded or handled explicitly before fitting.

## Environment Setup

Required runtime and packages:

- R >= 4.3 (validated on R 4.3.3).
- `Synth` (validated on 1.1-10) and `jsonlite` (validated on 2.0.0).
- Python >= 3.10 for the helper scripts (standard library only).

Install the R packages (run once):

```bash
Rscript -e '"'install.packages(c(\"Synth\",\"jsonlite\"), repos=\"https://cloud.r-project.org\")'
"'```

If you must pin the exact paper software, install the bundled source copy:

```bash
R CMD INSTALL code/Synth        # the Synth 1.1-10 source tree shipped in this repo
```

Pre-flight check (all three must print a version and the two `TRUE`s):

```bash
Rscript --version
Rscript -e '"'cat(as.character(packageVersion(\"Synth\")), as.character(packageVersion(\"jsonlite\")),
  requireNamespace(\"Synth\", quietly=TRUE), requireNamespace(\"jsonlite\", quietly=TRUE), sep=\"\\n\")'
python3 --version
"'```

Environment variables: none required. If `Rscript` is not on `PATH`, set it
explicitly for your shell, e.g. `export PATH="/path/to/R/bin:$PATH"`, or call the
estimator as `/path/to/Rscript scripts/estimate_synthetic_control.R ...`.

Offline fallback: `Synth`'"'s only hard runtime dependencies are "'`kernlab`,
`optimx`, and `rgenoud`. If CRAN is unreachable, install the vendored
`code/Synth` source tree plus those three packages from any local mirror, or use
the `--allow-fallback` donor-mean path (documented under Troubleshooting) to
produce a transparent, if less faithful, counterfactual.

## Inputs

| Name | Type / format | Required | Example |
| --- | --- | --- | --- |
| panel file | CSV named `*_panel.csv` | yes | `tobacco_panel.csv` |
| `unit_id` column | string | yes | `treated`, `donor03` |
| `period` column | numeric | yes | `1989` |
| `treatment_group` column | string (`treated`/`donor`) | yes | `donor` |
| `Z1` column | numeric predictor | yes | `1.899` |
| `Z2` column | numeric predictor | yes | `16.672` |
| `Y_observed` column | numeric outcome | yes | `39.7956` |
| treated periods | comma list, `--treated-periods` | no | `1989,1990,1991` |
| treated unit id | string, `--treated-unit` | no (default `treated`) | `treated` |
| pre-treatment window | `--pre-period-start`/`--pre-period-end` | no | `1980`/`1988` |

The panel must be one row per unit and period with at least two donor units and
at least two pre-treatment periods. Periods missing for any unit are dropped
during fit so the Synth matrices stay aligned.

## Outputs

- `answer.json` (path set by `--out`, default `./answer.json`):
  ```json
  {
    "counterfactual": {"1989": 29.235, "1990": 31.4303},
    "att": -7.4455,
    "rationale": "Synthetic control ... ATT = mean(observed - synthetic) ..."
  }
  ```
  - `counterfactual`: one finite number per requested treated period (keys are
    the period labels as strings).
  - `att`: finite number, the mean of `observed - counterfactual` over the
    requested periods.
  - `rationale`: non-empty free text describing the fit and donor weights.
- summary diagnostics (path set by `--summary-out`, optional): donor weights
  (`solution_w`), predictor weights (`solution_v`), `pre_treatment_mspe`,
  per-period `observed`/`counterfactual`/`gaps`.

## Procedure

Run all commands from your working directory (the one holding the panel file).
Paths are relative and portable; do not hardcode repository or home paths.

1. Locate the panel and confirm it parses. If the directory holds exactly one
   `*_panel.csv`, the estimator auto-discovers it; otherwise pass `--panel`.

   ```bash
   ls *_panel.csv

   ```

   Produces a JSON report with `unit_count`, `donor_count`, `treated_unit`,
   `common_period_count`, `blocking_issues` and `warnings`.
   Decision: if `status` is `error` or `blocking_issues` is non-empty, fix the
   panel (missing columns, fewer than two donors, non-numeric outcome) before
   proceeding. Warnings about unbalanced periods are acceptable.

2. Decide the treated periods and pre-treatment window. If the treated unit rows
   carry `treatment_group == "treated"` for exactly the post-intervention
   periods, the estimator infers them; otherwise pass `--treated-periods`.

   ```bash

   # is a unit-level label with no within-period contrast)

     --panel tobacco_panel.csv \\

     --out answer.json --summary-out sc_summary.json
   "'```

   The estimator fits `dataprep()` + `synth()`, projects the donor-weighted
   `Y0plot` onto the treated periods, and writes `answer.json` plus stdout JSON
   `{"status":"ok","method":"synth","att":...}`.
   Decision: if stdout shows `"method":"donor-mean-fallback"`, the Synth fit
   failed and a transparent donor mean was used — inspect `stderr` and
   `sc_summary.json.synth_error` before trusting the number.

3. Inspect the fit quality in the summary. A pre-treatment MSPE near zero and
   donor weights concentrated on a few units indicate a faithful synthetic
   control.

   ```bash
   python3 - <<'"'PY'

   against the panel.

   ```bash

   "'```

   Prints `{"status":"ok", "att":..., "computed_att":..., "problems":[]}`.
   Decision: if `status` is `error`, read `problems` and repair `answer.json`

   the ATT is stable:

     --treated-periods 1989,1990,1991,1992,1993,1994,1995,1996,1997,1998,1999,2000 \\

     --genoud --out answer_genoud.json
   "'```

   Decision: if the ATT from the default, lag-augmented, and `--genoud` runs
   agree within a few percent, report the default run. If they diverge wildly,
   the fit is fragile — prefer the specs with the lowest pre-treatment MSPE and

## Troubleshooting

1. **`Rscript: command not found` / `Synth` missing.**
   Symptom: `estimate_synthetic_control.R` exits non-zero with
   `This script requires the '"'Synth' R package"'`. Remediation: install the R
   runtime and run the Environment Setup install command; verify with the
   pre-flight check. Fallback: run the estimator with `--allow-fallback` to emit
   a donor-mean counterfactual (flagged in `rationale`), or fit the vendored
   source tree with `R CMD INSTALL code/Synth`.

2. **`Panel is missing required columns ...` or non-numeric outcome.**
   Symptom: exit code 1 from `inspect_panel.py` with `blocking_issues`. Fix the
   CSV header/values so it has `unit_id,period,treatment_group,Z1,Z2,Y_observed`
   with numeric `period`/`Y_observed`. Re-run `inspect_panel.py` until
   `blocking_issues` is empty.

3. **`Could not infer treated periods` or `treated periods not present`.**
   Symptom: the estimator cannot find a within-period `treatment_group`
   contrast, or `--treated-periods` names periods the treated unit lacks.
   Remediation: pass `--treated-periods` with the exact treated periods, and
   confirm the periods exist in the panel via `inspect_panel.py`
   (`period_min`/`period_max`).

4. **Poor pre-treatment fit / large MSPE.**
   Symptom: `sc_summary.json.pre_treatment_mspe` is large relative to the
   outcome variance, or donor weights are diffuse. Remediation: add
   `--lag-periods` for pre-period outcomes, narrow `--pre-period-start`/
   `--pre-period-end`, adjust `--predictors`, or enable `--genoud` for a global
   pre-search. If the fit stays poor, the donor pool cannot span the treated
   unit — document this rather than trusting the ATT.

5. **`Synth fitting failed: ...` (e.g. `At least one predictor in X0 has no
   variation across control units`).**
   Symptom: Synth stops because a predictor is constant across donors.
   Remediation: drop that predictor with `--predictors Z1` (keep at least one
   varying predictor), or use `--allow-fallback`. Confirm the choice is recorded
   in `rationale`.

# Slurm Job Array Starter

Use this skill to submit a tiny real Slurm job array, wait for terminal accounting, and summarize per-task outputs in compact JSON.

## What it does

- Renders and submits a minimal `sbatch --array` script on the live cluster.
- Polls queue state with `squeue` and waits for terminal task accounting with `sacct`.
- Reads each task's stdout and stderr logs and exports a per-task summary.
